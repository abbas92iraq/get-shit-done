# 01 — تحليل المجال (Domain Analysis)

## 1. خطوط الأعمال الأربعة وفروقاتها الجوهرية

الخطأ الأكثر شيوعاً في أنظمة المقاولات هو معاملة الأربعة خطوط بنفس النموذج. كل خط له **دورة إيراد** و**وحدة ربحية** و**دورة نقد** مختلفة تماماً:

| البُعد | المقاولات الإنشائية | التطوير العقاري | الصيانة والتشغيل (FM) | الخدمات الهندسية |
|--------|---------------------|-----------------|----------------------|------------------|
| **وحدة الربحية** | المشروع / العقد | الوحدة العقارية / المرحلة | عقد الخدمة / الأصل | المهمة / التكليف |
| **نموذج الإيراد** | نسبة الإنجاز (IFRS 15) — مستخلصات | تسليم الوحدة أو الإنجاز مع الوقت | اشتراك دوري + أوامر عمل | مراحل تسليم أو ساعات عمل |
| **الكلفة الرئيسية** | مواد + مقاولين ثانويين + معدات | الأرض + الإنشاء + التمويل | العمالة + قطع الغيار | ساعات المهندسين |
| **دورة النقد** | سلبية (تمويل مسبق ثم مستخلص) | سلبية جداً (سنوات) | إيجابية (تحصيل مقدم) | متوسطة |
| **الخطر الأكبر** | تجاوز الكلفة والتأخير والمطالبات | المخزون غير المباع والتمويل | خرق اتفاقية مستوى الخدمة SLA | إعادة التصميم غير المدفوعة |
| **المستند المحوري** | المستخلص (IPC) والأمر التغييري | عقد البيع وجدول الأقساط | أمر العمل والعقد | ورقة الوقت والمخرج |
| **القياس الحرج** | EVM (CPI/SPI) والنقد الحر | IRR وسرعة البيع | استجابة SLA و MTTR | معدل الاستغلال Utilization |

**النتيجة التصميمية:** نبني **نواة مشتركة** (المالية، المشتريات، المخازن، الموارد البشرية، المستندات، الجودة، السلامة) + **أربع وحدات خط أعمال** تركب فوق النواة، وكل شركة تفعّل ما يخصها. هذا يمنع تضخم النظام ويسمح ببيعه لشركة صيانة صغيرة أو مجموعة تطوير كبرى بنفس القاعدة.

## 2. البنية التنظيمية للشركة المستهدفة

النظام يجب أن يعكس هرمية تنظيمية مرنة بأربعة مستويات على الأقل:

```
المجموعة (Group)
 └── الشركة / الكيان القانوني (Legal Entity)      ← دفتر أستاذ مستقل، ملف ضريبي مستقل
      └── الفرع / المنطقة (Branch / Region)        ← مركز ربحية
           └── القطاع / الإدارة (Division)          ← إنشاءات | تطوير | صيانة | استشارات
                └── القسم (Department)              ← مركز تكلفة
                     └── المشروع / العقد / الموقع    ← وحدة التنفيذ
                          └── حزمة العمل (WBS)      ← أصغر وحدة قابلة للقياس والتكلفة
```

كل كيان في النظام يحمل **مسار تنظيمي (Org Path)** يُستخدم في: الصلاحيات، التقارير المجمّعة، توزيع المصاريف غير المباشرة، ومصفوفة الاعتمادات.

## 3. الشخصيات المستخدمة (Personas) — 22 دوراً

| المجموعة | الأدوار |
|----------|---------|
| **القيادة** | رئيس مجلس الإدارة، المدير العام، المدير التنفيذي للعمليات، المدير المالي |
| **المشاريع** | مدير المشاريع، مدير المشروع، مهندس الموقع، مساح الكميات (QS)، المخطّط (Planner)، مراقب التكاليف |
| **الدعم الفني** | مهندس الجودة، مسؤول السلامة، مراقب المستندات، مهندس التصميم |
| **سلسلة التوريد** | مدير المشتريات، مسؤول المشتريات، أمين المخزن، مدير المعدات |
| **المالية** | المحاسب، المدقق الداخلي، أمين الصندوق، مسؤول الرواتب |
| **الموارد البشرية** | مدير الموارد البشرية، مسؤول شؤون الموظفين، مسؤول العلاقات الحكومية |
| **الصيانة** | مدير المرافق، منسق مركز الاتصال، الفني الميداني |
| **التطوير والمبيعات** | مدير المبيعات، مندوب المبيعات، مسؤول التحصيل |
| **خارجي** | العميل، الاستشاري، المقاول الثانوي، المورّد، المستثمر |

كل دور له: لوحة معلومات مخصصة + قائمة مهامي (Inbox) + صلاحيات محددة + تطبيق جوال أو ويب.

## 4. المشاكل التي يحلها النظام (تبرير الاستثمار)

| المشكلة الواقعية | كيف يحلها النظام | الأثر المتوقع |
|------------------|-------------------|----------------|
| كلفة المشروع الحقيقية تُعرف بعد شهور من انتهائه | دفتر كلفة لحظي: كل صرف مواد/ساعة معدة/عمالة يُرحّل فوراً لكود الكلفة | إغلاق شهري في 3 أيام بدل 30 |
| المستخلصات تتأخر بسبب فوضى المستندات والقياسات | ربط قياس الكميات → موافقة الاستشاري → المستخلص آلياً | تسريع التحصيل 20–40 يوم |
| مواد تُشترى مرتين أو تُهدر في المواقع | حجز المخزون، تحويل بين المواقع، جرد بالباركود | خفض هدر المواد 5–12% |
| المطالبات والأوامر التغييرية تضيع ولا تُطالَب | سجل مطالبات مرتبط بالمراسلات والتأخيرات مع تنبيهات المدد التعاقدية | استرداد مطالبات كانت تُهدر |
| المعدات معطّلة أو غير مستغلة دون علم الإدارة | عدادات ساعات، صيانة وقائية، معدل استغلال لكل معدة | رفع الاستغلال 15%+ |
| قرارات الإدارة مبنية على تقارير Excel متأخرة ومتضاربة | مصدر حقيقة واحد + لوحات لحظية | قرارات أسرع وأدق |
| ضعف الالتزام بالسلامة والجودة وتوثيقها | تصاريح عمل، طلبات فحص، عدم مطابقات — كلها رقمية ومؤرشفة | جاهزية تدقيق ISO فورية |

## 5. حدود النطاق (Scope Boundaries)

**داخل النطاق:** كل ما يخص إدارة الشركة والمشاريع والعمليات والمالية والموارد.

**خارج النطاق (تكامل لا بناء):**
- برامج التصميم والنمذجة (AutoCAD / Revit) — نتكامل عبر IFC/BIM360 لا نبنيها.
- التحليل الإنشائي (ETABS / SAP2000).
- المحاسبة القانونية للمراجع الخارجي — نصدّر له لا نستبدله.
- أنظمة البنوك — نتكامل عبر ملفات SWIFT/ISO 20022 أو API.

## أسئلة مفتوحة للمناقشة

1. أي خط أعمال هو **الأولوية الأولى** للإطلاق؟ (توصيتي: المقاولات الإنشائية لأنها الأصعب والأغنى، وبقية الخطوط تستفيد من نواتها).
2. هل توجد أنظمة قائمة يجب الهجرة منها (بيانات تاريخية، حسابات، مشاريع جارية)؟
3. حجم الشركة المستهدف: كم مشروع نشط متزامن؟ كم موظف؟ كم مستخدم؟ — يحدد قرارات الأداء والبنية التحتية.
