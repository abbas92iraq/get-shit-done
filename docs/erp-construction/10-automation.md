# 10 — الأتمتة الكاملة للفعاليات

طلبك كان: **"يحقق النظام أتمتة كاملة للفعاليات"**. الأتمتة الكاملة لا تعني إلغاء الإنسان — تعني أن **الإنسان يقرر فقط، ولا ينقل بيانات ولا يتذكر مواعيد ولا يطارد أحداً**.

## 1. المستويات الخمسة للأتمتة

| المستوى | الوصف | مثال في النظام |
|---------|-------|-----------------|
| **1. أتمتة الإدخال** | البيانات تُلتقط لا تُكتب | باركود المواد، بصمة الحضور، GPS المعدات، OCR الفواتير |
| **2. أتمتة الترحيل** | حركة واحدة تولّد كل آثارها | استلام مادة ⇒ مخزون + ذمم دائنة + كلفة + طلب فحص |
| **3. أتمتة الانسياب** | المستند يمشي وحده بين المعتمدين | طلب شراء يصل للمعتمد الصحيح حسب القيمة والمشروع |
| **4. أتمتة المراقبة** | النظام ينتبه بدل الإنسان | تنبيه انتهاء إقامة، اقتراب خرق SLA، تجاوز موازنة |
| **5. أتمتة القرار المساعد** | النظام يقترح ويشرح | ترشيح أفضل عرض سعر، توقع EAC، ترتيب أوامر العمل |

---

## 2. محرك سير العمل (Workflow Engine)

**محرك واحد لكل النظام** — لا سير عمل مكرر في كل نطاق.

```
WorkflowDefinition (تعريف)
├── doc_type: "PurchaseRequisition"
├── trigger: on_submit
├── steps[]:
│    ├── step: "فحص آلي"      type: SYSTEM    rules: [budget_check, stock_check]
│    ├── step: "اعتماد المشروع" type: APPROVAL  resolver: matrix(DoA)   sla: 24h
│    ├── step: "اعتماد المالية" type: APPROVAL  condition: amount > 50M  sla: 48h
│    └── step: "إصدار"        type: SYSTEM    action: create_rfq
├── escalation: notify_manager after sla, auto_escalate after 2×sla
└── on_reject: return_to_originator with reason (إلزامي)
```

**خصائص إلزامية:**
- **مصمم مرئي** — المستخدم الإداري يعدّل المسار بلا مطوّر.
- **شروط ديناميكية** — تفرّع حسب القيمة، المشروع، نوع المصروف، الكيان القانوني.
- **اعتماد متوازٍ ومتسلسل** — "أي اثنين من ثلاثة" أو "الكل بالترتيب".
- **تفويض تلقائي في الغياب** — مرتبط بنظام الإجازات.
- **تصعيد زمني** — لا مستند يموت في صندوق أحد.
- **إعادة توجيه وطلب معلومات** دون إلغاء المسار.
- **سجل كامل** — من اعتمد، متى، من أي جهاز، بأي تعليق.

## 3. محرك القواعد (Rules Engine)

القواعد **بيانات لا كود** — تُعدَّل من الشاشة.

| فئة القاعدة | أمثلة |
|-------------|-------|
| **قواعد منع (Blocking)** | لا صرف مادة بلا كود كلفة · لا أمر شراء يتجاوز الموازنة بلا اعتماد استثنائي · لا تصريح عمل لعامل شهادته منتهية · لا مستخلص لبند لم يُفحص · لا بيع وحدة محجوزة |
| **قواعد تنبيه (Warning)** | مورّد تقييمه أقل من 3 · سعر أعلى 15% من آخر شراء · نشاط على المسار الحرج تأخر · مخزون تحت الحد الأدنى |
| **قواعد اشتقاق (Derivation)** | حساب المحتجز والضريبة والاستقطاعات · توزيع المصاريف غير المباشرة · احتساب الاستهلاك · تحديد مستوى الاعتماد |
| **قواعد تشغيل (Triggering)** | إنشاء طلب شراء تلقائي عند نقطة إعادة الطلب · إنشاء أمر عمل وقائي عند بلوغ ساعات التشغيل · إنشاء مهمة تجديد قبل 60 يوماً من انتهاء وثيقة |

## 4. الفعاليات المؤتمتة بالكامل (بلا تدخل بشري)

| الفعالية | المشغّل | الناتج |
|----------|---------|--------|
| ترحيل كلفة المواد | صرف من المخزن | قيد كلفة + قيد محاسبي |
| ترحيل كلفة العمالة | اعتماد ورقة الوقت | توزيع الراتب على أكواد الكلفة |
| ترحيل كلفة المعدات | تسجيل ساعات التشغيل | تحميل بالسعر الداخلي |
| المطابقة الثلاثية | وصول فاتورة المورّد | قبول أو رفض آلي مع بيان الفروقات |
| احتساب الاستهلاك الشهري | إقفال الفترة | قيود الأصول الثابتة |
| احتساب المحتجزات والاستردادات | اعتماد المستخلص | خصومات آلية |
| توليد الصيانة الوقائية | تاريخ أو ساعات تشغيل | أوامر عمل مجدولة |
| توليد أقساط عقارية | توقيع عقد البيع | جدول أقساط + تذكيرات |
| تنبيهات انتهاء الوثائق | يومياً | مهام تجديد للمسؤول |
| تنبيهات المدد التعاقدية | حدث تأخير/تغيير | إنذار بمهلة إشعار المطالبة |
| التسوية البنكية | استيراد كشف الحساب | مطابقة آلية + استثناءات فقط للمراجعة |
| تحديث منحنى S و EVM | تحديث التقدم | لقطة محسوبة |
| توقع التدفق النقدي | أي حركة مالية | تحديث توقع 13 أسبوعاً |
| الفوترة الإلكترونية | اعتماد الفاتورة | إرسال للهيئة + استلام التصديق |
| تقارير دورية | جدول زمني | إرسال PDF/Excel للمعنيين |
| إغلاق أمر العمل | توقيع المستفيد + تحقق | إيقاف SLA + فوترة |

## 5. الإشعارات الذكية

**المشكلة:** أنظمة ERP تغرق المستخدم بإشعارات فيتجاهلها كلها.

**الحل المصمم:**
- **تجميع (Digest):** ملخص واحد صباحي بدل 40 إشعاراً.
- **تصنيف بالإلحاح:** حرج (فوري، دفع + رسالة) · مهم (بريد) · معلوماتي (داخل النظام فقط).
- **قناة حسب الدور:** المهندس الميداني ⇒ إشعار دفع. المدير المالي ⇒ بريد. القيادة ⇒ ملخص أسبوعي.
- **قابلية الإجراء:** كل إشعار فيه زر اعتماد/رفض مباشر بلا فتح النظام.
- **تحكّم المستخدم:** كل مستخدم يضبط ما يريد استلامه وكيف.
- **منع التكرار:** حدث واحد = إشعار واحد مهما تعددت المسارات.

**قنوات:** داخل النظام · دفع للجوال · بريد · SMS · واتساب · Microsoft Teams/Slack (اختياري).

## 6. صندوق "مهامي" الموحّد (Unified Inbox)

كل مستخدم له شاشة واحدة تجمع **كل** ما ينتظر منه عبر الـ 27 نطاقاً:

```
مهامي (23)
├── اعتمادات معلقة (8)      ← أوامر شراء، إجازات، مستخلصات
├── متأخرة عني (3)  🔴      ← تجاوزت SLA
├── طلبات معلومات (4)       ← RFI، استفسارات
├── مهام مسندة (5)          ← إغلاق عدم مطابقة، تجديد وثيقة
└── للعلم (3)               ← لا تتطلب إجراء
```
مرتبة بالأولوية والاستحقاق، مع اعتماد جماعي (Bulk Approve) للبنود المتشابهة.

## 7. طبقة الذكاء الاصطناعي — أتمتة ما لا تقدر عليه القواعد

| القدرة | الأثر التشغيلي |
|--------|----------------|
| قراءة فاتورة المورّد وتعبئتها آلياً | إلغاء الإدخال اليدوي، خطأ أقل |
| قراءة كشف الحساب البنكي وتسويته | تسوية بنكية في دقائق |
| تصنيف المراسلات الواردة وربطها بالمشروع والمطالبة | لا مراسلة تضيع |
| تنبؤ تأخير المشروع من نمط التقدم | إنذار قبل 4–8 أسابيع |
| تنبؤ الكلفة النهائية (EAC ذكي) | قرار مبكر بدل مفاجأة نهائية |
| كشف الشذوذ (أسعار، تكرار موردين، صرف غير معتاد) | مكافحة الاحتيال |
| تحليل صور الموقع لكشف مخالفات السلامة | امتثال مستمر |
| جدولة الفنيين المثلى (موقع + مهارة + قطع غيار) | استجابة أسرع، وقود أقل |
| مساعد محادثة على بيانات الشركة | إجابة فورية بدل طلب تقرير |
| تقدير أولي من مشاريع مشابهة | تسعير أسرع وأدق |

**الحوكمة:** كل مخرج ذكاء اصطناعي مُعلَّم بوضوح، له **درجة ثقة**، ويحتاج **اعتماداً بشرياً** قبل أي أثر مالي، ويُسجَّل في سجل التدقيق.

## 8. مقاييس نجاح الأتمتة

نقيس الأتمتة لا ندّعيها:

| المؤشر | الهدف |
|--------|-------|
| نسبة المستندات المعتمدة دون تدخل يدوي إضافي | > 80% |
| متوسط زمن دورة الاعتماد | < 24 ساعة |
| نسبة الفواتير المطابقة آلياً | > 85% |
| نسبة الإدخال اليدوي المُلغى | > 60% مقارنة بالوضع السابق |
| زمن الإقفال الشهري | ≤ 3 أيام عمل |
| نسبة التنبيهات التي أدت لإجراء | > 40% (مؤشر جودة لا كمية) |
| نسبة أوامر العمل المُغلقة ضمن SLA | > 95% |
